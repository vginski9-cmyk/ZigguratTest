## Architecture Overview

Ziggurat is a **Next.js 16 App Router** application using **TypeScript**, **SQLite** (via better-sqlite3 + Drizzle ORM), and the **Anthropic Claude API**.

```
┌─────────────────────────────────────────────────────┐
│                    FRONTEND                          │
│  Next.js App Router (React 19, Client Components)   │
│  Pages: Dashboard, Submit, Review, Profiles          │
├─────────────────────────────────────────────────────┤
│                    API LAYER                          │
│  Next.js Route Handlers (/api/*)                     │
│  submit, agent1, agent2, validate, profiles, ejcp    │
├─────────────────────────────────────────────────────┤
│                  AGENT LAYER                         │
│  invoke.ts → Anthropic SDK → Claude Haiku 4.5        │
│  agent1-prompt.ts (Ziggurat Classifier)              │
│  agent2-prompt.ts (Skill Profiler)                   │
├─────────────────────────────────────────────────────┤
│                  DATA LAYER                          │
│  Drizzle ORM → better-sqlite3 → ziggurat.db          │
│  WAL mode enabled for concurrent access              │
└─────────────────────────────────────────────────────┘
```

### Key Design Decisions

- **SQLite + WAL mode** — No external database server needed. WAL mode allows concurrent reads during long-running agent calls.
- **Claude Haiku 4.5** — Cost-optimized model. Swap to Sonnet or Opus for higher quality at higher cost.
- **Client Components** — All pages use `"use client"` for interactive state management. API calls happen from the browser.
- **Version tracking** — Every EJCP and skill profile stores version history. Reviews create new versions rather than mutating existing records.
- **JSON repair** — Agent responses are sometimes truncated. The system includes intelligent JSON repair logic that closes incomplete structures.

## Data Flow: End to End

This is the complete lifecycle of a job description through the pipeline:

### Step 1: Submit Job Description

```
User pastes JD text → POST /api/submit
```

- The raw text is hashed (SHA-256) for deduplication
- A `job_descriptions` record is created with a UUID
- Returns: `{ id: "<uuid>" }`

**File:** `src/app/api/submit/route.ts`

### Step 2: Agent 1 — Ziggurat Classifier

```
Frontend sends jdId → POST /api/agent1
```

- Fetches the JD text from the database
- Sends it to Claude with the Agent 1 system prompt (~3500 lines)
- Claude classifies the JD across all 27 context layers
- Each layer gets: `value`, `confidence` (0-100), `provenance` (extracted/inferred/unknown), `evidence` (quoted text)
- Also extracts explicit skills and infers implicit skills
- Generates clarifying questions for low-confidence layers
- Response is parsed, validated, and stored as an `ejcp_versions` record (status: `ai_enriched`)
- A `review_queue` entry is created (gate: `gate1`, status: `pending`)
- Returns: `{ ejcpId: "<uuid>" }`

**Files:**
- `src/app/api/agent1/route.ts` — API route
- `src/lib/agents/agent1-prompt.ts` — System prompt
- `src/lib/agents/invoke.ts` — Claude invocation + JSON parsing

### Step 3: Gate 1 Review

```
Reviewer opens /review/gate1/[ejcpId]
```

- Displays all 27 context layers grouped by category
- Shows confidence badges (red < 50%, yellow 50-85%, green >= 85%)
- Shows provenance badges (extracted/inferred/unknown)
- Shows evidence quotes from the original JD
- Reviewer can edit layer values using dropdowns/multi-select
- Reviewer can answer clarifying questions generated by Agent 1
- When satisfied, clicks "Validate & Send to Agent 2"

```
Frontend sends edited data → POST /api/validate (entityType: "ejcp")
```

- Creates a new `ejcp_versions` record (version incremented, status: `human_verified`)
- Marks the gate1 queue item as `completed`
- Returns the new EJCP ID

**File:** `src/app/review/gate1/[id]/page.tsx`

### Step 4: Agent 2 — Skill Profiler

```
Frontend sends ejcpId → POST /api/agent2
```

- Fetches the validated EJCP data
- Sends it to Claude with the Agent 2 system prompt
- Claude generates structured skill profiles (max 10 skills)
- Each skill includes: definition, BGI category, skill labels, criticality, 3-level proficiency descriptions, KSA requirements, learning modalities, education program mappings (CIP codes), partnership viability assessment
- Also generates brief sections for business, learner, and educator audiences
- **Retry logic:** If response is truncated, retries with max 6 skills
- **Prefill trick:** Forces raw JSON output by prefilling the assistant response with `{\n  "meta":`
- Response is parsed and stored as a `skill_profiles` record (status: `ai_enriched`)
- A `review_queue` entry is created (gate: `gate2`, status: `pending`)
- Returns: `{ profileId: "<uuid>" }`

**Files:**
- `src/app/api/agent2/route.ts` — API route with retry logic
- `src/lib/agents/agent2-prompt.ts` — System prompt
- `src/lib/agents/invoke.ts` — Claude invocation + JSON repair

### Step 5: Gate 2 Review

```
Reviewer opens /review/gate2/[profileId]
```

- Displays each skill as a detailed card with all fields
- Shows the EJCP context panel alongside for reference
- Reviewer can edit skill fields inline
- Reviewer marks each skill: approved / needs_revision / rejected
- Tracks warning counts (unreviewed skills, low confidence)
- When satisfied, clicks "Validate & Publish"

```
Frontend sends edited data → POST /api/validate (entityType: "profile", gate: "publish")
```

- Creates a new `skill_profiles` record (status: `published`)
- Creates `skill_reviews` records for each individual skill decision
- Marks the gate2 queue item as `completed`
- Returns the published profile ID

**File:** `src/app/review/gate2/[id]/page.tsx`

### Step 6: Published Profile

```
User views /profiles/[profileId]
```

- Three tabs: Overview (context layers + skills summary), Skills (detailed skill cards), Brief (business/learner/educator narratives)
- Read-only view of the finalized profile

**File:** `src/app/profiles/[id]/page.tsx`

| Column | Type | Description |

## API Routes

All routes are in `src/app/api/`.

| Method | Route | Purpose | Timeout |
|--------|-------|---------|---------|
| POST | `/api/submit` | Save a job description | Default |
| POST | `/api/agent1` | Run Agent 1 (Ziggurat Classifier) | 120s |
| POST | `/api/agent2` | Run Agent 2 (Skill Profiler) | 180s |
| POST | `/api/validate` | Save reviewed data, increment version | Default |
| GET | `/api/profiles` | List all published profiles | Default |
| GET | `/api/profiles/[id]` | Get a single profile + EJCP | Default |
| GET | `/api/ejcp/[id]` | Get an EJCP by ID | Default |

```json

```

**POST /api/agent1**
```json

```

**POST /api/agent2**
```json

  "entityType": "profile",
  "entityId": "770e8400-...",
  "gate": "publish",
  "data": { /* edited profile data */ },
  "skillReviews": { "skill-1": "approved", "skill-2": "rejected" },
  "reviewerId": "reviewer-name"
}
```

## Agent System

### How Agent Invocation Works

**File:** `src/lib/agents/invoke.ts`

The `invokeAgent()` function wraps the Anthropic SDK:

1. Creates an Anthropic client using `ANTHROPIC_API_KEY` from environment
2. Sends a `messages.create` call with:
   - Model: `claude-haiku-4-5-20251001`
   - System prompt (from agent1-prompt.ts or agent2-prompt.ts)
   - User message containing the JD text or EJCP data
   - 5-minute timeout
3. Extracts the text response
4. Passes it through `parseAgentJSON()` which:
   - Strips markdown code fences if present
   - Extracts JSON from the response
   - If the JSON is truncated (common with large outputs), runs repair logic that intelligently closes open arrays, objects, and strings

### Agent 1: Ziggurat Classifier

**File:** `src/lib/agents/agent1-prompt.ts`
**Token limit:** 16,384

The prompt defines:
- All 27 context layers with their enum values
- Classification rules (3-tier provenance: extracted 90-100%, inferred 50-89%, unknown <50%)
- Skill extraction rules (explicit from JD text + inferred from context)
- Output JSON schema
- Instructions for generating clarifying questions

### Agent 2: Skill Profiler

**File:** `src/lib/agents/agent2-prompt.ts`
**Token limit:** 32,768

The prompt defines:
- BGI skill taxonomy categories
- Skill label definitions (durable, high-growth, high-value, declining)
- Proficiency level framework (3 levels per skill)
- KSA requirements structure
- Learning modality rankings
- Education program mapping (CIP codes)
- Partnership viability assessment criteria
- Brief section requirements (business, learner, educator)

**Special behaviors:**
- **Prefill trick:** The assistant response is prefilled with `{\n  "meta":` to force raw JSON output (no markdown wrapping)
- **Retry logic:** If the first response is truncated, a second attempt is made with instructions to limit to 6 skills maximum

### Changing the Model

In `src/lib/agents/invoke.ts`, find the model constant:

```typescript
const MODEL = "claude-haiku-4-5-20251001";
```

Change this to use a different model:
- `claude-sonnet-4-5-20250514` — Higher quality, higher cost
- `claude-opus-4-20250514` — Highest quality, highest cost

## The 27 Ziggurat Context Layers

**Definition file:** `src/lib/ziggurat/enums.ts`
**Type definitions:** `src/lib/ziggurat/types.ts`

The layers are organized into 4 categories:

### Category 1: Company & Economic Role

| Layer | Name | Type | Values |
|-------|------|------|--------|
| L2 | Business Model | Multi-select | product, service, subscription, platform, freemium, outcome_based |
| L3 | Financial Health | Single | bootstrapped, seed, series_a_b, series_c_plus, profitable, public |
| L4 | Scale | Single | micro (1-10), small (11-50), medium (51-250), large (251-1000), very_large (1000+) |
| L5 | Lifecycle | Single | courtship, go_go, adolescence, prime, stable, aristocracy, decline |
| L6 | Digital Maturity | Single | analog, transitioning, integrated, ai_augmented |
| L7 | Geography | Single | urban_core, suburban, rural, distributed, international |
| L8 | Regulatory Environment | Single | unregulated, lightly_regulated, heavily_regulated, safety_critical |

### Category 2: Role & Work Architecture

| Layer | Name | Type | Values |
|-------|------|------|--------|
| L9 | Role Level | Single | entry, experienced, senior, manager, director_exec |
| L11 | Interaction Intensity | Multi-select | solitary, transactional, cross_functional, partner, service, care, enforcement, high_visibility |
| L12 | Dreyfus Proficiency | Single | novice, advanced_beginner, competent, proficient, expert |
| L13 | Tooling Complexity | Multi-select | office_productivity, specialized_software, hand_tools, machinery, legacy_systems |
| L14 | Work Mode | Composite | physical: onsite/hybrid/remote; temporal: standard/shift/on_call/flexible |
| L15 | Cognitive Load | Composite | cognitive: vigilance/switching/deep_focus/procedural; sensory: fine_motor/spatial/auditory/aesthetic |
| L16 | Interdependence | Single | pooled, sequential, reciprocal |
| L17 | Liability/Risk | Multi-select | incidental, financial, reputational, safety, legal, national_security |

### Category 3: Compensation & Job Quality

| Layer | Name | Type | Values |
|-------|------|------|--------|
| L18 | Career Mobility | Multi-select | credential_based, experience_based, career_lattice |
| L19 | Employment Relationship | Composite | type: w2_full/w2_part/1099/temp; benefits: full/partial/none; union: yes/no |
| L21 | Work Design | Composite | psychosocial_safety, task_autonomy levels |
| L22 | Growth & Supervision | Composite | supervision_model, worker_voice, advancement levels |
| L23 | Schedule Predictability | Single | volatile, variable, predictable, fixed, flexible |

### Category 4: Measurement & Training

| Layer | Name | Type | Values |
|-------|------|------|--------|
| L25 | Instructional Readiness | Single | none, adhoc, standardized, dedicated |
| L25.2 | Partnership Capacity | Single | E1 (low clarity, low constraint) through E4 (high clarity, low constraint) |

Each layer classification includes:
- **value** — The selected enum value(s)
- **confidence** — 0-100 score
- **provenance** — extracted (from JD text), inferred (from context), or unknown
- **evidence** — Quoted text from the JD supporting the classification

## Component Reference

All reusable components are in `src/components/`.

### ZigguratContextPanel

**File:** `src/components/ZigguratContextPanel.tsx`

Renders all 27 context layers grouped by category. Supports both read-only and edit modes. Shows confidence badges, provenance tags, and evidence quotes for each layer.

**Props:**
- `data` — EJCP data object with layer values
- `editable` — Boolean to enable edit mode
- `onChange` — Callback when a layer value is changed

### SkillDetail

**File:** `src/components/SkillDetail.tsx`

Full skill card displaying: definition, BGI category, skill labels, criticality, 3-level proficiency descriptions, KSA requirements (knowledge, skills, abilities), preferred learning modalities, education program mappings (with CIP codes), partnership viability assessment, and review controls (approve/reject/needs revision).

### SkillPills

**File:** `src/components/SkillPills.tsx`

Skill selection/navigation UI. Renders skills as clickable pills, either flat or grouped by BGI category. Includes separate `ExtractedSkillPills` and `InferredSkillPills` variants for the Gate 1 review.

### ProfileBrief

**File:** `src/components/ProfileBrief.tsx`

Renders the three brief sections generated by Agent 2: `for_business`, `for_learner`, `for_educator`. Supports inline editing in review mode.

### ReviewControls

**File:** `src/components/ReviewControls.tsx`

Sticky footer bar with the validate/publish button. Displays warning counts (unreviewed skills, low-confidence layers) and disables the button until all required actions are complete.

### EnumSelector

**File:** `src/components/EnumSelector.tsx`

Generic selector component driven by the `multi` prop:
- `multi: true` → Renders as a grid of toggle buttons (multi-select)

### ConfidenceBadge

**File:** `src/components/ConfidenceBadge.tsx`

- Red: < 50%

### ProvenanceBadge

**File:** `src/components/ProvenanceBadge.tsx`

Tag showing whether a classification was `extracted` (from JD text), `inferred` (from context), or `unknown`.

## Key Domain Types

**File:** `src/lib/ziggurat/types.ts`

```typescript
// Core EJCP structure
interface EJCP {
  meta: { jd_id: string; employer_id?: string; agent_version: string; timestamp: string };
  context_layers: Record<string, LayerClassification>;
  extracted_skills: Skill[];
  inferred_skills: Skill[];
  clarifying_questions: ClarifyingQuestion[];
  data_quality: DataQualityScore;
}

// Individual layer classification
interface LayerClassification {
  value: string | string[];    // Enum value(s)
  confidence: number;           // 0-100
  provenance: "extracted" | "inferred" | "unknown";
  evidence: string;             // Quoted JD text
}

// Skill profile output from Agent 2
interface SkillProfile {
  meta: { ejcp_id: string; agent_version: string; timestamp: string };
  skills: StructuredSkill[];
  brief: {
    for_business: string;
    for_learner: string;
    for_educator: string;
  };
}

// Individual structured skill
interface StructuredSkill {
  id: string;
  name: string;
  definition: string;
  bgi_category: "core_role_specific" | "baseline_applied" | "foundational_leadership" | "specialization";
  labels: string[];             // durable, high_growth, high_value, declining
  criticality: "must_have" | "important" | "nice_to_have" | "contextual";
  proficiency_levels: { level_1: string; level_2: string; level_3: string };
  ksa: { knowledge: string[]; skills: string[]; abilities: string[] };
  learning_modalities: LearningModality[];
  education_mapping: EducationMapping;
  partnership_viability: PartnershipViability;
}
```

## Extending the Pipeline

### Adding Agent 3 (Education Mapper)

This is the most obvious next step. Based on the PRD:

1. **Create the prompt** at `src/lib/agents/agent3-prompt.ts`
   - Input: Validated skill profile + EJCP context
   - Output: Detailed education program mappings with CIP codes, curriculum alignment, competency crosswalks

2. **Create the API route** at `src/app/api/agent3/route.ts`
   - Follow the pattern in `agent2/route.ts`
   - Fetch the published skill profile
   - Invoke Claude with the Agent 3 prompt
   - Store results in a new table

3. **Create the review page** at `src/app/review/gate3/[id]/page.tsx`
   - Add Gate 3 review interface
   - Add appropriate review controls

4. **Add the database table** in `src/lib/db/schema.ts`
   - `education_mappings` table following the same pattern as `skill_profiles`

5. **Update the review queue** to support `gate3`

### Adding Authentication

Currently the app uses a simple static password (`REVIEWER_PASSWORD` in `.env.local`). To add real auth:

1. Add an auth library (NextAuth.js, Clerk, or similar)
2. Protect the `/review/*` routes
3. Populate `reviewer_id` fields from the authenticated user
4. Add role-based access (reviewer, admin, viewer)

### Adding Batch Processing

To process multiple JDs at once:

1. Create a batch upload page (CSV/JSON upload)
2. Create a `/api/batch` endpoint that queues JDs
3. Process them sequentially or with controlled concurrency
4. Add a batch status dashboard

### Swapping the Database

SQLite works well for single-server deployments. To scale:

1. Update `drizzle.config.ts` to use PostgreSQL dialect
2. Change `better-sqlite3` to `pg` or `@neondatabase/serverless`
3. Update `src/lib/db/index.ts` with the new connection
4. Run `npm run db:push` to apply schema to the new database
5. Drizzle ORM abstracts most queries, so minimal code changes needed

### Adding Data Export

1. Create `/api/export/[profileId]` route
2. Support JSON and CSV formats
3. Include EJCP context + skills + brief sections
4. Consider adding PDF generation for formal reports
